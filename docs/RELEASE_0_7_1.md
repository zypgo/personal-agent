# 0.7.1：缺陷修复

这一版基于 0.7.0 的 `c187d020aa4259b91921d9d621fb3756da25c701`，做了代码审查和缺陷修复。现有的界面、Agent 工具、记忆、提醒、审批、渠道、协作和执行能力，都保留；没有数据库迁移，也没有新增依赖。

## 确认并修好的问题

| 范围 | 什么情况下触发，原来的问题是什么 | 怎么修的 |
| --- | --- | --- |
| 文件访问边界 | 列目录之前，路径已经校验过；但并发的操作，把这个目录或它的上级目录，换成了指向工作区外的符号链接，仍然可能列出外部的文件名和大小 | 从可信的根目录出发，通过目录描述符逐级遍历，每一级目录，都拒绝跟随后来才出现的链接；元数据查询，也不跟随链接 |
| 预算保护 | 扩额或配置，接受了 Infinity；扩额还接受 NaN，有限的大额相加，也可能溢出，导致支出上限失效 | 配置、CLI 和核心层，都检查有限值和加总是否溢出；旧库里不合法的扩额，回退到配置的上限；同一天的增额，在事务里累加 |
| 请求解析 | 小于请求大小上限的深层 JSON，会抛出递归异常，接口返回 500，配对入口没有把它计入失败限流 | 配对、审批和 V3/V4 的 JSON 入口，统一返回 400；配对失败，仍然计入限流 |
| 手机面板 | 标题栏提前捕获了关闭按钮的触摸，导致按钮收不到点击；第二根手指，还可能覆盖拖动状态 | 交互控件，不参与标题栏的拖动捕获，只保留一个主指针 |
| 图片发送 | SSE 先确认了消息，POST 随后失败，本地图片预览的 URL 没有释放 | 一收到确认，就回收本地预览，正式的图片，继续用已经授权的媒体地址 |
| 菜单手势 | 拖动过程中旋转屏幕，或者跨过布局断点，会留下半开的状态，并且阻塞后面的手势 | 布局切换、开合和销毁的时候，统一清理拖动状态 |
| 空间与账号切换 | 旧空间的预算、设备数量和操作提示，没有跟着列表一起清空 | 登出、切换空间或权限变化的时候，同步清理诊断和提示，并取消旧提示的计时器 |
| 发布配置检查 | 有多个环境文件，或者同一个文件里重复定义了同名变量时，前面的敏感值，被后面的值覆盖，扫描因此漏检 | 累积所有定义里的值，逐个检查；拒绝信息，仍然不显示值本身 |
| 发布标签检查 | 提交作者检查，不覆盖附注标签自己的作者邮箱 | 检查新标签和嵌套标签的作者；已有的公开标签对象，不在这次发布范围里，不重写也不移动它们 |

## 更新与回退

按现有的部署流程，更新到 0.7.1。版本号同步到包、运行时和 OpenAPI；Service Worker 用运行时版本，管理公共页面的缓存，私人 API 仍然不进入离线缓存。

没有数据库迁移。原来保存的、非有限的预算扩额，会按零处理；配置文件里的无限预算，现在会被明确拒绝，需要改成有限的正数。必要的话，可以重新部署 0.7.0，但这一版修好的问题会随着回退而回来。
