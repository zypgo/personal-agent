# 把文件发给你

`publish_artifact(path, name=None, description="")` 会把工作区里一个已经写好的文件，做成一份不能再改的私有快照，然后排一条通知。工具返回的是入队回执（queue receipt）。送达由原有的投递器（Dispatcher）确认，文件也由它记进对话历史。

## 怎么用

让 agent 在它的工作区里生成报告、表格、压缩包或别的文件，再发布出来。例如：

```text
创建 workspace/reports/summary.csv，再把 reports/summary.csv 发布出来，附言写“你要的汇总。”
```

路径相对于 `PA_HOME/workspace`，这个目录里的绝对路径也可以用。带 `..` 的路径、符号链接、硬链接、目录、管道和设备文件，会被拒绝。发布之前，文件必须已经完整写完。

文件工具和成果文件功能都打开时，主人发起的 run 和定时 run 可以用这个工具。它属于 `net_write` 策略类别，走平时的审批规则；由外部内容触发的 run 和做梦（整理记忆）的 run 用不了它。

策略规则按相对工作区的规范路径匹配：`private/report.txt`、`./private/report.txt` 和它的绝对路径，都能匹配 `publish_artifact:private/*` 这样的规则。

## 怎么送到你手上

| 渠道 | 结果 |
| --- | --- |
| Web | 对话历史里出现一张文件卡片。下载要用已经配对的浏览器会话。 |
| Telegram | 一次 `sendDocument` multipart 上传，通知文字作为附言。收件人必须仍然是配对过的。 |
| 其他渠道，包括钉钉 | 发一条文字通知，指引主人去已登录的 Web 对话里取文件。如果 Web 关着，通知里会说要先把它打开。 |

所有配对过的 Web 设备，都属于同一个主人，和现有的对话历史一样。

`GET /api/artifacts/{id}`：没有有效的 Web 会话，返回 `401`；快照不可用，返回 `404`；过期之后，返回 `410`。下载一律按文件下载（`Content-Disposition: attachment`），HTML 和 SVG 也一样，不会在应用页面里显示。

历史记录的格式保持稳定：

```json
{
  "kind": "artifact",
  "meta": {
    "run_id": "产生这个文件的 run",
    "artifacts": [{
      "id": "32 位小写十六进制",
      "name": "summary.csv",
      "mime": "text/csv",
      "size": 1234,
      "sha256": "64 位小写十六进制",
      "expires_at": 1800000000
    }]
  }
}
```

这份元数据是服务端从自己的存储里生成的。客户端用 `id` 拼出需要登录的下载路径。MIME 类型只是按文件名给出的显示提示。

## 大小限制和保留时间

```toml
[artifacts]
enabled = true
max_file_bytes = 10485760      # 10 MiB；最多可以调到 50 MiB
max_total_bytes = 209715200    # 没过期的快照，一共 200 MiB
max_active_files = 1000        # 空文件也占一个名额
retention_days = 30
```

说明文字最多 500 个字符。下载文件名里不能有路径分隔符或控制字符，也不能超过 240 个 UTF-8 字节。总配额至少要能装下一个最大尺寸的文件。超过任何一项限制，都会报错，什么也不会入队。

名字和附言里如果带有已配置的凭据，或者看起来像凭据的内容，发布前会被拒绝。只检查名字和附言，不扫描文件内容。

过期的内容，马上就读不到了。守护进程每天的整理、启动时的恢复、新的发布，会清掉过期的内容块（blob），和没提交成功的内容块。元数据留在 SQLite 里，用于历史记录和去重。字节配额不限制数据库里的历史记录保留多久。主人已经从浏览器或 Telegram 里存下来的文件，不受本地的保留时间管。

## 崩溃和重试

快照放在可写工作区之外、只有主人能进的目录里，文件权限是 `0600`。下载和上传在把字节交给渠道之前，都会核对存下来的长度和 SHA-256。

先写内容块，并 fsync。然后，它的元数据和发件箱消息，在同一个 SQLite 事务里提交。出了错，通知会跟着回滚。如果进程在提交之前崩了，可能留下一个没有登记的内容块，恢复的时候会把它删掉。已经提交的发布，重启之后依然有效，也不再依赖工作区里的原文件。

去重的键是 `(session_key, work_id, source_path)`。重试同一个任务，返回的是原来的快照和通知，就算工作区里的文件已经被改过或删掉。同一个任务里，不同的路径，是不同的结果。要在同一个任务里发布修正后的版本，请换一个新路径。之后的任务有新的 work ID，可以再次发布原来的路径。

主人主动要的文件，不受静默时段限制；定时任务发的文件，要遵守静默时段。上传结果不确定的，一律停在 `maybe_sent`，主人主动发起的上传，和被进程崩溃打断的上传，也一样。Telegram 在发送之前连接失败，或者明确被限流，可以重试。被永久拒绝的，就是失败。发生得比较晚的读写失败，和服务器错误，不会自动重发。`pa outbox` 会列出还没有结论的投递。主人可以去聊天里看一眼，需要的话，再让它重新发布一次。

Telegram 上传之前，会再检查一次配对和收件人。
