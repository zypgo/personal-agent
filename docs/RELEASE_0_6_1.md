# 0.6.1：给日常，多一点从容

这一版继续把 Personal Agent 做成面向个人的产品。默认的聊天、可以收起的菜单，和全部的底层能力，沿用 0.6.0，这一版集中调整视觉、反馈，和那些容易打断操作的细节。没有新增服务、前端依赖、数据库迁移或后端业务逻辑。

## 设计

原创的四瓣标记，贯穿连接入口、菜单和聊天。欢迎区用轻量的轨道图形，表达想法一步步展开；四个快捷起点是：理清待办、安排提醒、整理资料、交办任务。快捷入口只是把内容准备到输入框，不会替你发送，也不会发起工作。

画布改成了纸白，正文用深灰绿，陶土色突出主操作，鼠尾草绿和淡紫区分内容。深色外观用深绿的底色和浅色的字。继续用系统字体和本地的 SVG/CSS 图形，不请求外部字体或图片。

| 页面 | 调整 |
| --- | --- |
| 个人助理 | 两行的欢迎标题、四个图形入口；输入区把文字和操作栏分开，附件、语音和发送，仍然是原来的能力 |
| 菜单 | 四瓣的品牌标记、图标底座、明确的选中状态，开合有短暂的过渡；桌面端记住收起的选择，手机端保留遮罩和焦点约束 |
| 待办卡片 | 类型标签、内容和操作，分成几层；忙碌提示依据真实的请求，审批和成果验收，保持原来的确认步骤 |
| 任务 | 圆角的类型切换、选中的卡片、紧凑的步骤时间线；去掉了原来步骤顶部不必要的大段留白 |
| 资料 | 目录和编辑区分层、纸页样式的空状态；保存之后，历史入口马上可用 |
| 助手、项目、设备 | 各栏目有自己的图形、分组的表单和空状态，管理和连接的全部入口，都保留 |

动效只用在：第一次出现、悬停、点击，和真实的忙碌状态。装饰没有循环飘动；手机的触摸，不用靠悬停，才能发现操作。系统设置了“减少动态效果”的话，会关掉动画、过渡和主动的平滑滚动。

## 复核与修复

| 问题 | 修复 |
| --- | --- |
| 多图导入部分失败，已经成功的附件没有预览，却可以发送 | 导入成功或失败结束的时候，同步附件的预览；保留现有的数量预留和会话隔离 |
| 编辑失败的消息，覆盖了当前新的草稿，或者超过了图片上限 | 有输入、附件或媒体正在准备时，两份内容都保持原位；恢复之前，再校验一次图片上限 |
| 输入框延迟的焦点回调，在退出之后访问旧页面 | 延迟的回调，先核验原来的 composer 仍然属于当前会话 |
| 手机双指放大，被当成键盘弹出，强制缩高并滚到底 | 只在正常的缩放比例下，才应用键盘补偿；放大阅读时，保留滚动位置 |
| 移除附件的按钮，被滚动容器裁切，热区太小 | 按钮放进缩略图的边界里，点击区域扩大到 44px |
| 快捷指令被标成列表框，却没有对应的方向键行为 | 用真实的按钮组语义，沿用 Tab 和点击操作 |
| 切换外观，重建了按钮，导致键盘焦点丢失 | 保留按钮节点，只更新选中状态，用 `aria-pressed` |
| 麦克风等待权限时，禁用按钮导致失焦，录音开始之后，很难停下 | 禁用之前，记住触发时的焦点；权限返回之后，按实际的焦点，决定要不要接力，结束后恢复；不会抢走用户主动移开的焦点 |
| 新资料第一次保存之后，历史按钮被旧状态再次禁用 | 提交结束之后，按新的 revision，恢复历史按钮，失败时仍然保持正确的状态 |
| 重复点击当前的任务，重绘并丢掉详情里的草稿 | 电脑任务和协作任务，在当前详情有草稿，或者提交在途的时候，保持编辑的对象 |
| 取消保存连接的确认框之后，草稿保护被清除 | 取消会返回明确的结果，表单只在真正完成的时候，才清除 dirty 标记 |
| 编辑连接，使用固定的平滑滚动 | 和其他页面一致，尊重“减少动态效果”的偏好 |
| 很长的助手名，可能挤进头部按钮的区域 | 标题限制在实际可用的宽度内，并截断，保留菜单和待办的操作 |

所有动态的内容，仍然用安全的 DOM 构建。没有改动身份、空间和成员的权限、执行确认、审批版本、消息去重或卡片的执行屏障。

## 验证范围

完整的质量门禁 `scripts/check.sh` 通过：

- Python：**5974 passed，24 skipped**。跳过项和上一版一样：23 项需要 macOS，1 项需要 restic；真实模型测试单独排除。
- JavaScript：**238 passed，0 skipped**，比 0.6.0 多了 15 项交互回归，包含部分图片导入失败、6 类草稿占用、附件容量、异步会话隔离、主题和录音焦点、缩放、资料历史和任务草稿。
- Ruff、Mypy 的 203 个源模块、TypeScript、API 类型生成和构建的一致性，通过。
- OpenAPI 和 0.6.0 比较，只有 `info.version` 变了。5 份 CSS，通过了 PostCSS 语法解析。
- 发布的文件，用默认的 Gitleaks 规则扫描，不用仓库的忽略规则，没发现密钥。
- 独立的代码审查和无障碍复核里，明确的问题都已修复；最后一轮，没有发现新的阻断项。

自动化回归，用的是可控的媒体、视口、请求和 DOM 测试环境，不调用真实的模型、外部助手或生产任务。审查和测试，能降低出缺陷的风险，但不代表证明了绝对没有缺陷。

浏览器的本地预览，受 URL 安全策略的限制，这次没有绕过这个限制，也没有改生产的鉴权来获得截图。部署之后，可以检查公开的入口和资源；登录之后的桌面和手机视觉，还没有实测，不能把静态检查或模拟的 DOM，当作完整的视觉验收。
