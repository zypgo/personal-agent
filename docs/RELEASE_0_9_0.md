# 0.9.0：像人一样说话，每件事一条线，加一个 Obsidian 知识库

这一版做了三件事：栖序说话的方式更像人；交给其他助手的每个任务各成一条线，做完自己收拾；多个助手的成果有了共同的知识库，用 Obsidian 就能打开。数据库从 v14 升到 v15（新增两张表），没有新增依赖。

动手之前，先读了 19 个开源项目（Grok Bot 一类的团队 bot、线程式的任务管理、Obsidian 和 LLM wiki 的做法），读法和取舍见[对比和取舍](research/reference-analysis.md)第十节。里面所有代码都是独立写的；没有许可证或是 AGPL 的项目，只读想法。

## 说话更像人

| 地方 | 做法 |
| --- | --- |
| 怎么说话 | 提示词里加了一段说话的规矩：一条消息一个要点，一到四句；先给答案，再补充；要列表才给列表；只说新的，不复述你刚说过的；最多问一个问题，你没回答就先假设着往下做；能直接做的先做完再说；不同意，一句话说清理由 |
| 分条发 | Telegram 和钉钉上，几句话的纯文字回复，按段落拆成最多 3 条，间隔 0.5–2.5 秒，Telegram 在间隔里显示“正在输入”。带格式的（代码、列表、表格、标题）、超过 700 字的、紧急的、带文件的、要你批准的，整条发，不会被切开。`[chat] bubbles = false` 可以关掉，`max_bubbles` 改条数 |
| 助手的消息 | 交给其他助手的任务，有话要对你说的时候（提问、交回结果、没做成、联系断了），用固定的中文句子，不调用模型，每次都是同一个说法，也不花钱。例如：“Grok 有个问题要你拿主意：用哪个数据源？直接回我就行，我转给它。” |
| 安静 | 做着的时候不吵你。只在这几种时候出声：要你拿主意、结果交回来了、没做成。 |

## 每件事一条线

交给其他助手（Grok、Muse、你自己的 Agent）的任务，现在每个任务就是一条线，有自己的状态，也有人替你照看：

- **状态**：做着、等你（批准 / 回答 / 验收 / 确认）、做完、没做成、已收起。
- **提醒**：任务卡住了，说一次；等你的事，45 分钟后提醒一次，24 小时后再一次，最多这两次（`[threads] remind_minutes`、`remind_again_hours`）。不想被提醒的任务，在任务页点“先别提醒”。服务刚启动（比如刚升级）、或者电脑刚从睡眠里醒来的那段时间，不算在助手头上，从那一刻起重新计时；一次有三件以上要说，合成一条。
- **自动收起**：做完 24 小时后自动收起，不再占着列表（`[threads] archive_after_hours`，0 为不收）。没做完、还在等你的，不会被收起。
- **规则是固定的**，不靠模型判断；`pa serve` 在后台定时巡检。
- **任务页**：顶上多了筛选（全部 / 等你处理 / 已收起）；每个任务有一个状态标签和下一步该做什么；可以收起、取消收起、先别提醒；每个任务旁边有“在知识库里看这条线索”。等你的排在最前面。
- **助手自己也看得到**：栖序每次回复前，会收到一份“现在有哪些任务、哪几个在等你”的清单，你问“那个调研怎么样了”，它直接知道是哪一个。

## 知识库（Obsidian）

原来菜单里的“资料”，改成了“知识库”：一个文件夹的 Markdown 笔记。你、栖序、接进来的助手都往里写；Obsidian 直接打开这个文件夹就能看、能改，属性、`[[链接]]`、反向链接、关系图都能用。

- **文件就是真相。** 你在 Obsidian 里改了，栖序下次读到的就是新的，不用同步。想放进你已有的仓库：`[vault] path = "~/Documents/笔记/栖序"`；运行 `pa vault open` 交给 Obsidian。
- **四个文件夹。** `wiki/` 是留下来的知识；`raw/` 是外面来的原始资料，只增不改；`threads/` 是升级之后交出去的任务，每个一篇；`daily/` 是每天发生了什么。另外自动生成 `wiki/index.md`（目录）和 `wiki/log.md`（改动记录）。
- **多个助手共用。** 每个助手交回的结果，原样存成 `raw/agents/<助手名>/` 下的一篇，记着是哪个助手、哪个任务、哪一步、结果怎样；同一份结果存两次，只有一篇。任务笔记里只放链接。每个项目空间有自己的知识库。
- **谁的话，写在属性里。** `origin`：你、栖序、别的助手、网页、读了外面内容之后写的（`tainted`）、系统。栖序没法冒充你。`private: true` 的笔记和 `[vault] exclude` 里的文件夹，助手看不到。出现密钥的内容，写不进去。
- **聊天里直接用。** “记一下：预算每月五号提交”“上次预算那件事是怎么定的？”栖序会先查再答，值得留的才记，往已有的笔记里加，不另起一篇。你的笔记，除非你要求，它不整篇改写。
- **每一笔都能撤销。** 网页里打开一篇看历史、恢复一个版本；命令行 `pa vault log`、`pa vault restore`、`pa vault undo`。保留 180 天。你在之后改过的笔记，撤销时不会被覆盖。
- **以前的“资料”**：第一次启动时搬进 `wiki/`（只搬一次，原文件不删），旧的入口和接口照常能用。

完整的说明，见[知识库：和 Obsidian 一起用](KNOWLEDGE_BASE.md)。

### 每夜整理

夜里的“做梦”，除了记忆，也会照看知识库，但守得更紧：只在 `wiki/` 和 `daily/` 里新增，或往它自己写的笔记后面追加，不碰你写的笔记；看一眼 `raw/` 里还没有被链接的资料，把意思写成 wiki 笔记，链回原文；一晚最多新建 6 篇（`[dreaming] max_new_notes`）；这一晚没做完，或者因为删记忆太多被整个撤销，它写的笔记也一并撤回。

## 命令行

新增 `pa vault`：看文件夹在哪、有多少篇、有什么要看一眼；`search` 找笔记；`lint` 查断掉的链接、没人链接的笔记、还没整理的资料、重名；`open` 交给 Obsidian；`index` 马上重写目录；`log` 看最近的改动；`restore` 和 `undo` 撤销。这些命令只看和撤销，不改笔记的内容。

## 网页接口

新增：`/api/v3/vault`、`/vault/notes`、`/vault/note`（读和写）、`/vault/history`、`/vault/restore`、`/vault/lint`；任务线的 `/api/v4/tasks/{id}/archive`、`/unarchive`、`/snooze`。接口文档和 TypeScript 类型已经重新生成。任务的返回里多了一个 `thread` 字段（阶段、标签、下一步、是否收起、先别提醒到什么时候、对应的笔记）。原来的接口没有改。

## 更新与回退

先备份 `~/.personal-agent`（或你的 `PA_HOME`），再更新依赖并重启：

```bash
uv sync --frozen
uv run pa serve
```

数据库的 schema 从 14 升到 15：新增 `vault_versions`（笔记的改动历史）和 `threads`（任务线）两张表，旧数据不动。正在运行的服务，提示词和页面是启动时读进内存的，重启之后才会换成新的。知识库的文件夹第一次用时才会创建。

要回退到 0.8.1，需要同时恢复升级前的数据库备份；旧版本会拒绝较新的 schema，不能只回退代码。知识库文件夹里的笔记是普通文件，回退后依然在。
