# 0.9.3：服务放在别处，自己的电脑只管给 Codex 干活

有人问：服务已经放在 Railway 这样的地方了，我只想让自己的 Mac 当 Codex（或者 Cursor）的执行端，平时在浏览器里用，不想在电脑上再跑一遍整个项目。能不能做到？

能，而且这条路早就有：电脑上只装一个 `pa` 命令行，让它去领网页上批准的任务。但以前这条路要自己拼命令、查编号，我也没真的用 Codex 走通过。这一版是我在 Mac 上用真的 Codex 从头走了一遍，哪里卡住改哪里。

数据库还是 v15，没有新增依赖，接口没有变（只是版本号）。

## 现在是什么样

1. 在网页的「助手与连接 → 连接 Agent」里选 Codex（或 Cursor），保存。
2. 弹出的窗口里除了凭据，还有一条**现成的命令**：服务地址、Agent 编号、空间编号都填好了。以后重新启动，在这个连接的卡片里复制第二条。
3. 在要干活的电脑上，先 `cd` 到一个没有未提交改动的 Git 项目，粘贴运行。它停下来等凭据时，回到窗口点「复制」，粘贴进去，按回车。凭据不在命令行里，也不会进命令历史。
4. 之后在网页里批准的任务，会由这台电脑上的 Codex 领走，在一个独立的 worktree 里干活，你的项目不会被改。干完交回补丁，由你验收。

电脑上只装 `pa`：

```bash
uv tool install --python 3.13 /path/to/personal-agent
```

不启动任何服务，不会碰你原来的数据。

## 真的跑起来以后，改了这几处

| 问题 | 以前 | 现在 |
| --- | --- | --- |
| Codex 明明做完了 | 在 macOS 上，网页里显示“结果未知”，这台电脑的 Host 之后也不肯再接任务，要手动核对才能解开 | 正常显示“成果待验收”，附上补丁 |
| Codex 想运行命令，要你批准 | 一大段原样的 JSON（里面一半是编号和时间），选项是 `accept` / `decline` / `cancel` | “Codex 想运行这条命令：…，在这个目录里：…”，选项是“允许”“拒绝”“拒绝并停止” |
| 电脑上找不到 `codex` | 先把任务领走，再失败，任务标成“未知”，这台电脑的 Host 之后不肯再跑 | 一开始就说：`Cannot find 'codex' on this computer…`，这时还没有领任何任务 |
| 任务卡在“等待领取” | 写着“保存后页面会给出现成的命令”（连接早就保存了） | “要在你的电脑上运行 pa 命令行，才会领取任务。” |

第一行是这次最值得说的。macOS 有个习惯：一个程序结束了、但启动它的程序还没来得及“收尸”时，系统不肯说它属于哪个进程组。Host 靠进程组确认“Codex 和它拉起来的所有子进程都停了”，问不出来，就当成没法确认，于是把一次成功的任务标成“结果未知”。原来的测试都用不会出现这种状态的假程序，所以没碰到；换成真的 Codex，第一次就碰上了。现在这种“已经结束、等着被收”的进程，算作已经停了。

“拒绝”只是跳过这一步，Codex 会接着想别的办法；“拒绝并停止”会结束这一次执行。命令总是完整显示，不会截短；Codex 附带的其他信息（比如要联网访问哪个地址）也照原样写在下面，只有标识这条请求的编号和时间不显示。

## 没验证的，和没做的

- **Cursor** 没有在真实账号上试过：这台电脑上没装 Cursor 的命令行。命令和 Codex 是同一套，但没走通过。
- **Linux** 没试过。
- **没登录 Codex** 的情况，没有提前检查：现在只会在找不到程序时马上提醒。没登录会怎样，我没试；按代码看，任务会被领走，然后失败，被标成“结果未知”，要按 [CLOUD_AGENTS.md](CLOUD_AGENTS.md) 里的步骤核对。
- Codex 每运行一条命令，都要你在网页里点一次“允许”。一个小任务两三条，大任务会很多。没有“这次任务里都允许”：这是有意的，批准一直是一条一条给的。
- 这台电脑要一直开机、不休眠、能上网，才接得到任务。
- Codex 在结果文字里写的文件路径，是它那个 worktree 里的路径，在网页上只是一段文字。要看改了什么，下载补丁或者新文件包。

## 更新与回退

服务这一边，把新版本推到部署用的仓库，平台会自动重新部署，大概半分钟，期间网页打不开。数据不受影响。

电脑这一边，只要重新装一次命令行：

```bash
uv tool install --python 3.13 --reinstall /path/to/personal-agent
pa --version
```

要回退到 0.9.2，换回代码就行：数据库没有变化。已经保存的连接和凭据继续有效，命令行用同样的状态目录。
