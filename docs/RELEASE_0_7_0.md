# 0.7.0：更灵动，更像一件原生应用

0.7.0 把整个前端从头到尾打磨了一遍：视觉、动效、手势和操作动线。能力沿用 0.6.1，没有新增服务、前端依赖、数据库迁移，接口也没有变化。

这是第一个在真实视口里逐页看过渲染结果的版本：手机、小屏手机、平板和桌面，浅色与深色，登录前、离线以及有数据的状态。0.6.1 的发布说明坦承登录后的桌面与手机视觉尚未实测；这一版补上了，并修掉了只有看到画面才会发现的问题。

## 设计语言：柔和玻璃

聊天页与各栏目页共用一份 `tokens.css`：颜色、字号、圆角、阴影、玻璃和动效曲线只定义一次，两个页面不会再各改各的。

| 层面 | 做法 |
| --- | --- |
| 色彩 | 浅色是纸白，深色是深林绿。一份令牌用 `light-dark()` 同时描述两种外观，不支持它的浏览器回到浅色。正文、辅助文字、状态色与图标对比度由测试逐项计算 |
| 字体 | 仍只用系统字体（含苹方），统一的字号阶梯；不请求外部字体或图片 |
| 形状 | 统一的圆角阶梯。支持连续曲率圆角（squircle）的浏览器用它画卡片、输入与按钮，其余回落为普通圆角 |
| 层次 | 三档阴影；顶栏与输入区是半透明的模糊玻璃，内容从它们下面滑过 |
| 动效 | 弹性与缓出两条曲线、三档时长；只有新出现的内容才有入场动画。系统开启“减少动态效果”时，动画、过渡、页面转场与平滑滚动全部关闭 |
| 栏目色 | 对话陶土、任务鼠尾草、资料琥珀、助手紫、项目蓝、设备灰绿。图标底座和选中态使用栏目色；栏目色用作文字时先向正文色调和，保证可读 |

## 对话

- 头部的四瓣标记随状态变化：空闲、正在忙、等你处理、连接中断。
- 助手的回复边生成边排版，标题、列表和代码在文字到达时就位，不再等整段结束后一次跳变。
- 输入区是一枚圆润的胶囊：附件在左，语音在右；输入文字后语音变为发送。多行输入随内容增高。
- 欢迎语随时段问候；四个快捷起点只把示例填进输入框，不替你发送。
- 助手在做什么用日常说法描述，例如“正在搜索网页…”“正在阅读文件…”，而不是内部工具名；不认识的工具统一说“使用工具”。
- 临时反馈用提示条；偏好设置与图片预览从底部升起。在手机上按住顶部的抓手向下拉即可放下，轻扫一下也行。

## 菜单与操作动线

- 手机上在页面空白处向右拖动即可拉出菜单，菜单跟手展开；松手时按位置与速度决定打开或回弹。向左拖动、点遮罩或按 Escape 收起。屏幕最左侧的窄条留给浏览器的返回手势；输入框、代码块、表格和对话框里的拖动不会触发菜单。
- 菜单展开时焦点进入菜单并被限制在其中，收起后回到触发它的按钮。桌面端展开菜单时，页面里不再重复出现一个菜单按钮。
- 聊天与各栏目页之间交叉淡入；栏目页内切换任务、资料、助手、项目、设备时在同一页内过渡，同时更新标题与菜单选中项。
- 栏目页向下滚动后，顶栏会显示当前栏目的名字，回到顶部时恢复，滚得再远也知道自己在哪一页。
- 保存成功、已取消之类的提示浮在顶栏下方，不随页面滚动，几秒后自己消失，点按即可收起；出错提示不会自动消失。

## 栏目页

- 每个栏目有大标题、一句说明和带栏目色的图标底座；操作按钮在手机上缩进到文字下方，不再与标题错位。
- 创建表单收在一张卡片里，点加号展开，再点收起。任务页的“助手协作 / 电脑任务”是带滑动指示的分段控件。
- 各栏目的卡片使用同一组间距、圆角和阴影；所有折叠项使用同一个会随展开旋转的箭头。
- 手机上的对话框（一次性代码、资料历史）以底部面板呈现。含一次性代码的对话框只能由“我已保存”或 Escape 关闭，点背景不会误关。

## 在真实渲染里发现并修复的问题

| 问题 | 修复 |
| --- | --- |
| 手机上向左滑动无法关闭菜单：浏览器把横向拖动当作页面平移，手势到不了菜单 | 菜单与遮罩声明只接受纵向平移和双指缩放；打开和关闭两个方向都用真实触摸序列验证，并有测试守住 |
| 滚动之后，保存成功等提示留在页面顶部，已经滚出屏幕，看不到 | 提示改为固定浮在顶栏下方，几秒后自行消失 |
| 辅助文字（时间、占位符）对比度在浅色下只有 2.9:1、深色下只有 2.6:1 | 提高到不低于 4:1；测试按两种外观计算所有文字与底色的对比度 |
| 栏目色直接用作文字，琥珀与浅蓝在纸白上难以阅读 | 文字使用向正文色调和后的颜色，图标底座保持原色；测试守住 |
| 浏览器自带的折叠三角在聊天卡片与栏目页里大小、位置不一 | 统一为同一个箭头 |
| 桌面端菜单展开时页面里还有一个重复的菜单按钮 | 展开时隐藏；开合时焦点按键盘与触摸分别处理 |
| 手机上标题旁的操作按钮换行后挤在标题下方 | 缩进到文字列下方对齐 |
| 平板上创建卡片的加号跑到标题前面，手机上卡片左侧留白过大 | 只在手机上调整顺序，统一卡片内边距 |

另有一处与界面无关的修复：在 macOS 上，Git 子进程因输出超限被终止时，进程组可能只剩已退出的残留，系统会回答“无权限”而不是“进程不存在”，这个错误会盖过本该报告的“结果超过上限”。现在与沙箱的终止逻辑一致，忽略这种情形并报告真实原因，并有确定性的回归测试。

## 验证范围

- Python：**6008 passed，30 skipped**；另在 Python 3.11 上完整运行，结果相同。跳过项是 28 项需要付费调用真实模型的测试（设置 `PA_LIVE=1` 才运行）、1 项需要 GNU timeout、1 项需要 restic。
- JavaScript：**252 passed，0 skipped**，较 0.6.1 增加 14 项。新增拖动手势、底部面板、提示条、栏目转场、问候语和菜单焦点的回归测试，并用变异检查确认这些测试在代码被故意破坏时会失败。
- 新增的设计守卫（Python）：两种外观下全部文字与图标的对比度、栏目色文字的可读性、回落色板与浅色一致、两个页面都先加载 `tokens.css`、减少动态效果时转场关闭、菜单与遮罩保留横向拖动。
- Ruff、Mypy、TypeScript、API 类型生成与构建一致性通过。OpenAPI 与 0.6.1 比较仅 `info.version` 变化。
- 视觉验证：逐页截图并查看。设备为 390×844 手机、375×667 小屏手机、820×1180 平板、1280×800 与 1680×1000 桌面；浅色、深色与减少动态效果；登录前、服务不可达，以及有任务、资料、助手与设备数据的状态。菜单滑动与底部面板下拉用触摸事件序列验证。

验证使用 Chrome 的移动视口与触摸模拟，没有覆盖真实 iOS Safari 与真机；连续曲率圆角、`light-dark()` 与页面转场在不支持的浏览器上会回落为普通圆角、浅色与无转场，功能不受影响。审查与测试能够降低缺陷风险，不代表证明绝对没有缺陷。

## 更新与回退

按原部署流程更新即可。页面文件每次都会向服务端校验（ETag），更新后无需手动清理缓存；私人 API 与凭据不进入离线缓存；浏览器本地仍只保存外观偏好与菜单展开选择。无数据库迁移，必要时可重新部署 0.6.1，保留现有持久数据。
