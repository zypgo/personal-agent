# 个人与小规模协作

## 第一次使用

先按 [MOBILE.md](MOBILE.md) 配好网页和手机，再用 `pa web pair --label phone` 给管理员生成一个一次性的设备链接。打开后，进入聊天页的“工作台”。私人空间适合放个人的对话和笔记；要和别人一起做事，先创建一个项目。

在项目的成员页里生成成员邀请。对方打开邀请链接后，选一个显示名称，就拥有了自己的身份、自己的私人空间，以及这个项目的成员资格。已经登录的成员加入新项目时，沿用原来的身份。首次显示的恢复码要保存好，关掉页面后不会再显示；注册不需要真实姓名或邮箱。

| 角色 | 读取项目 | 对话、笔记、任务 | 邀请和管理成员 | 批准项目的普通工具 | 批准机器执行 |
| --- | --- | --- | --- | --- | --- |
| viewer | 可以 | 不可以 | 不可以 | 不可以 | 不可以 |
| member | 可以 | 可以 | 不可以 | 不可以 | 不可以 |
| owner | 可以 | 可以 | 可以 | 可以 | 还要是相应资源的所有者 |
| 实例管理员 | 要先是项目成员 | 按项目角色 | 按项目角色 | 按项目角色 | 可以审查指定由本人审批的机器计划 |

实例管理员在应用里也看不到别人的私人空间。项目至少要留一名 owner；成员退出，不会删除共同的项目资料。任务和消息记着原来的发起人，重新加入的成员不会自动接回旧任务。

## 同一个人的手机、浏览器与恢复

“设备 → 本人配对”是给你自己再加一个浏览器；“成员邀请”是给另一个人。两者不能混用。iOS 的主屏幕 PWA 和 Safari，可能各有一套 cookie，要分别配对。

在设置页里，可以撤销你自己的设备，不能撤销别人的设备。所有设备都用不了时，用你保存的一次性恢复码。恢复时会撤销这个身份所有旧会话，作废它名下还没用的邀请和配对码（设备、渠道绑定、项目成员、节点），再签发一个新会话。已经完成的设备配对、节点注册和渠道绑定不受影响，恢复之后到设置页看一遍，把不认识的撤销掉。重新生成恢复码，会让之前的恢复码失效。

如果所有凭据都丢了，请有主机权限的管理员通过本地命令处理。

整个实例做过 `restore-all` 之后，旧的设备会话、邀请和恢复码都会失效。管理员在主机的终端里查看原来的身份 ID，再为需要恢复的已有身份生成一次性的设备链接：

```bash
pa web principals
pa web pair --principal EXISTING_PRINCIPAL_ID --no-qr
```

`principals` 列出 ID、显示名称和 active / disabled 状态。把 `EXISTING_PRINCIPAL_ID` 换成列表里的 ID；被禁用或不存在的身份不能配对。链接是 `/#pair=...` 的形式，由这位成员在自己的浏览器里打开一次。这个命令不创建身份，不新增成员，也不改变角色。管理员给自己配对，用普通的 `pa web pair`。Railway 的终端用 `python -m personal_agent.deploy admin web principals` 和 `python -m personal_agent.deploy admin web pair --principal EXISTING_PRINCIPAL_ID --no-qr`。

## 绑定 Telegram / 钉钉

1. 先在服务端配好并启动对应的官方渠道，见 [DINGTALK.md](DINGTALK.md) 和 README。
2. 在网页里切到你要访问的空间，生成一个一次性的渠道绑定码。
3. 在机器人的**私聊**里发送 `/bind CODE`。绑定码被用掉之后，这个渠道账号以后发的消息，就进入你选的那个空间。
4. 从另一个空间重新生成绑定码，会改变对应关系。旧空间里排着队的消息，仍然发给原来的空间。

绑定的是 bot / app / 组织账号加发送者。没绑定的陌生人发来的消息，不会交给 Agent；私聊的绑定也不适用于群聊。旧安装升级时，会保留已经批准的 owner 发送者。在主机上用 `pa channels approve/allow` 时，需要能确定对应的 bot / app；确定不了，就用网页的绑定流程。

## 共享知识库

知识库页读写当前空间自己的那份笔记：每个项目空间一个文件夹，私人空间的位置是 `[vault] path`（默认 `~/.personal-agent/vault`）。查看者只能读，成员和负责人可以写。支持搜索、看每一笔的历史、恢复旧版本，和版本号冲突检查。来源 URL 可以写在正文里，供成员和 Agent 引用。两个人同时编辑时，后提交的、基于旧版本的那一份会收到冲突，不会覆盖新内容。

接进来的 Agent 交回的结果，原样存在这个空间知识库的 `raw/agents/<助手名>/` 下，新交出去的任务，每个在 `threads/` 里有自己的一篇。Agent 之间不直接读对方的笔记，要用到别人的成果，由栖序读了再带进下一次派活。详细说明见 [KNOWLEDGE_BASE.md](KNOWLEDGE_BASE.md)。

以前的“资料”，第一次启动时搬进了 `wiki/`，旧入口保存的资料也会同步一份过去。

成果文件通过当前空间的 Artifact 接口下载，下载要有登录会话，并且有保留期。

## 任务与审批

工作台里能看到负责人、步骤、状态、日志和成果。修改目标时，用 revision 校验；要改命令，必须重新出计划。需要补充信息时，可以暂停任务；成员的回答按“单次问题”记录，重复提交相同的回答，结果一样（幂等），冲突的回答会被拒绝。

用别人的电脑，需要资源所有者先批准那份计划。管理员的“资源审批”只能看这些计划。提交计划时要知道：资源所有者和他的电脑，能看到要执行的命令和你发过去的输入。

节点离线，不等于任务失败；点击取消后，要等运行中的进程确认停止，才显示“取消完成”。状态是 `uncertain` 时，先到节点上看，不要重复新建任务。操作细节见 [EXECUTION.md](EXECUTION.md)。

## 排障

| 现象 | 检查和处理 |
| --- | --- |
| 邀请失效 | 确认邀请没被用过、没过期、签发的人仍有权限；到正确的项目里重新生成 |
| 返回 403 | 检查选的空间、角色、有没有被撤销；切回自己的私人空间 |
| 任务排队 | 检查节点在线、空间授权、能力声明，以及计划是否已批准 |
| 取消待确认 | 保留任务记录，等原来的节点上线核对 |
| 结果待核查 | 对照同一个 attempt 和固定的容器核对 |
| 消息没有推送 | 检查固定的渠道绑定、成员资格、Outbox 和平台的回执；PWA 没有系统通知 |
| 全局预算用完 | 聊天和语音会暂停需要付费的请求；状态查询、取消、人工处理照常可用 |
| 清理待确认 | 检查节点是否完成了容器和工作区的删除，并成功回报 cleanup；确认之前，收据一直保留 |

完整实例的恢复，请用 [V3.md](V3.md) 里的 `backup-all` / `restore-all`；单个 `pa db backup` 不包含其他空间和文件。
