# 个人与小规模协作

## 首次使用

先按 [MOBILE.md](MOBILE.md) 配好 Web/手机，使用 `pa web pair --label phone` 为管理员生成一次性设备链接。进入聊天页的“工作台”。私人空间适合个人对话和笔记；共同工作先创建项目，不要把自己的设备配对链接当成成员邀请发送。

在项目的成员页生成成员邀请。对方打开邀请链接后选择显示名称，获得自己的身份、私人空间和这个项目的成员资格；已登录的成员加入新项目会复用原身份。保存首次显示的恢复码，不用真实姓名或邮箱注册。邀请和恢复码只保存在当前页面内存，关闭后不再显示。

| 角色 | 读取项目 | 对话、资料、任务 | 邀请与管理成员 | 批准项目普通工具 | 批准机器执行 |
| --- | --- | --- | --- | --- | --- |
| viewer | 可以 | 不可以 | 不可以 | 不可以 | 不可以 |
| member | 可以 | 可以 | 不可以 | 不可以 | 不可以 |
| owner | 可以 | 可以 | 可以 | 可以 | 仍需相应资源所有者身份 |
| 实例管理员 | 必须属于该项目 | 同样受项目边界限制 | 同样受项目角色限制 | 同样受项目角色限制 | 可审查指定为本人审批的机器计划 |

即使实例管理员也不能通过应用读取别人的私人空间。服务器管理员对底层磁盘的访问不属于这一应用隔离承诺。项目至少保留一名 owner；成员退出不删除共同项目资料。任务与消息保留原发起人及授权版本，旧任务不会因重新加入而恢复。

## 同一个人的手机、浏览器与恢复

“设备 → 本人配对”用于增加自己的浏览器；“成员邀请”用于不同的人。两者不能混用。iOS 主屏幕 PWA 与 Safari 可能有独立 cookie，需要分别配对。

设置页可撤销本人的设备，不能撤销别人设备。全部设备不可用时使用保存的一次性恢复码，系统会撤销旧会话并签发新会话；重新生成恢复码会让之前的恢复码失效。遗失全部凭据时，由具有主机权限的管理员通过本地管理路径处理，不把秘密贴到项目对话或工单。

完整实例 `restore-all` 会使旧设备会话、邀请和恢复码失效。管理员先在可信主机终端查看原身份 ID，核对成员及现有项目权限，再为需要恢复的**既有有效身份**生成一次性设备链接：

```bash
pa web principals
pa web pair --principal EXISTING_PRINCIPAL_ID --no-qr
```

`principals` 只列 ID、显示名称和 active/disabled 状态。将 `EXISTING_PRINCIPAL_ID` 换成列表中的准确 ID；禁用或不存在的身份不能配对。链接仍使用 `/#pair=...`，由该成员在自己的浏览器打开一次；这一操作不创建身份、不新增项目成员、不改变角色。普通 `pa web pair` 继续用于管理员本人。Railway 终端使用 `python -m personal_agent.deploy admin web principals` 和 `python -m personal_agent.deploy admin web pair --principal EXISTING_PRINCIPAL_ID --no-qr`。

## 绑定 Telegram / 钉钉

1. 先在控制端配置并启动对应官方渠道，见 [DINGTALK.md](DINGTALK.md) 及 README。
2. 网页切换到要访问的空间，生成一次性渠道绑定代码。
3. 在机器人**私聊**发送 `/bind CODE`。代码被消费后，这个渠道账号的后续消息进入所选空间。
4. 从其他空间重新生成绑定代码，会显式改变映射。旧空间里排队的消息不会因为最近联系人改变而发到新空间。

绑定对象是 provider 账号范围（bot/app/组织）与 sender，不根据消息内容猜测身份。陌生人的普通消息不会进入 Agent；个人私聊绑定不自动授权群聊。旧安装迁移会保留当时已经批准的 owner sender。可信主机上的 `pa channels approve/allow` 仍需要能够确定对应 bot/app 范围，无法确定时使用网页绑定流程。

## 共享资料

资料页把 Markdown 写到当前空间的 `/memories/state/knowledge/`，支持搜索、最近 20 个版本的阅读和版本号冲突检查。来源 URL 可写入正文以供成员和 Agent 引用；资料中的外部内容不成为系统指令。两个人同时编辑时，较晚提交的旧版本会收到冲突，不覆盖新内容。

成果文件通过当前空间的 Artifact 接口下载，持有一个文件 ID 不足以跨空间访问。下载不是公开永久链接；它受当前会话、成员资格和成果保留期共同限制。

## 任务与管理员审查

工作台显示负责人、步骤、状态、日志和成果。目标修改使用 revision 校验；更改命令需要新计划。需要补充信息时可暂停任务，成员的回答按单次问题记录，重复相同回答幂等，冲突回答拒绝。

使用别人的电脑需要资源所有者审查冻结计划。管理员的“资源审批”只读取这些计划，不因此读取提交者的其他私人资料。提交计划时应理解：资源所有者及其执行电脑必然能看到要执行的命令与显式发送的输入。

节点离线不是任务失败；点击取消后，运行中的进程必须确认停止才显示取消完成。不要通过重复新建任务来处理 `uncertain`。操作细节见 [EXECUTION.md](EXECUTION.md)。

## 排障

| 现象 | 检查与处理 |
| --- | --- |
| 邀请失效 | 确认邀请未消费、未过期、签发者仍有权限；从正确项目重新生成 |
| 返回 403 | 检查所选空间、角色和是否被撤销；切回自己的私人空间 |
| 任务排队 | 检查节点在线、空间授权、能力声明和计划是否已批准 |
| 取消待确认 | 保留任务记录，让原节点上线核对；不可仅删除容器记录就声称未执行 |
| 结果待核查 | 对照同一 attempt 与固定容器；不要自动生成替代任务 |
| 消息没有推送 | 检查固定渠道绑定、成员资格、Outbox 与平台回执；PWA 没有系统通知 |
| 全局预算用尽 | 聊天/语音暂停付费请求，状态查询、取消和人工处理继续可用 |
| 清理待确认 | 检查节点是否完成容器/工作区删除并成功回报 cleanup；保留收据直到确认 |

完整实例恢复请使用 [V3.md](V3.md) 的 `backup-all` / `restore-all`，单个 `pa db backup` 不包含其他空间及文件。
