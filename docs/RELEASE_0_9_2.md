# 0.9.2：邀请别人进项目，从点开链接到说出第一句话，走通了

有人问：别人拿到邀请链接，新建身份或者验证身份之后，会不会自动进到共享的项目里，开始对话？

我没有只看代码，而是在真实的浏览器里把这条路走了一遍。每个人一个独立的浏览器环境，登录状态互不相干，分别扮演新人、已经登录的人、用恢复码回来的人、访客、拿着用过的链接的人、负责人自己，再加上负责人中途改权限、移出成员。

答案是：**不会**。新人加入后停在项目的“任务”页，要自己找“继续对话”；其他几条路也各有毛病。这一版把它们一个个改掉，再按同样的路线走了几遍。

数据库还是 v15，没有新增依赖。接口只增不改：`/api/v3/enroll` 多回了 `created`、`joined`、`space`、`role` 四项，新增两个接口：看邀请（`/api/v3/invites/preview`）和收回邀请（`/api/v3/invites/revoke`）。

## 点开链接以后

| 情况 | 以前 | 现在 |
| --- | --- | --- |
| 新人，第一次来 | 起昵称、保存恢复码之后，停在项目的“任务”页，要自己找“继续对话” | 点“我已保存，进入对话”，直接进项目的对话，顶上说一声“已加入「…」。这里说的话，项目里的人都看得到。” |
| 已经登录的人 | 点“接受邀请”，落在“项目与成员”页 | 页面先写明是哪个项目、谁邀请的、什么角色；点“加入并进入对话”，直接进对话 |
| 有账号，但这台设备没登录 | 先输恢复码，还要再点一次“接受邀请”，最后落在“项目与成员”页 | 输入恢复码，自动用这条邀请加入，进对话 |
| 邀请页 | 只写“接受项目邀请”，看不出是哪个项目、谁邀请的，还露着一个已经填好的邀请码输入框 | 标题是“加入「每周研究」”，下面写“某某邀请你以成员加入”，访客写明“能看，不能发言”；邀请码已经带在链接里，输入框不再露出来 |
| 链接用过了、过期了或者被收回了 | 一行英文错误 | 一句中文：“这条邀请已经失效：用过了，或者超过 24 小时。请让邀请你的人重新发一条。”不管是哪个原因，说法都一样 |
| 已经在项目里的人再点这条链接，包括负责人点自己发的 | 邀请被用掉了，真正要用的人打不开 | 只带进项目，邀请留着，还能发给别人 |
| 没登录的人看到的页面 | 一整列进不去的菜单，右上角还有个“继续对话” | 只有加入的表单 |
| 助手里的“加入项目”卡片 | 加入后停在原地 | 加入后直接进项目对话 |

发邀请的一边也改了：

| 情况 | 以前 | 现在 |
| --- | --- | --- |
| 邀请的有效期 | 10 分钟，发出去来不及看 | 24 小时，只能用一次。设备配对、聊天账号绑定、电脑配对还是 10 分钟 |
| 发错了，想收回 | 页面和命令里都没有入口 | 项目的成员页多了“撤销还没用的邀请” |
| 在 `127.0.0.1` 上生成的链接 | 照常生成，发出去对方打不开 | 生成时提醒“只有这台电脑打得开”；设置了对外访问地址，就自动用那个地址 |
| 一个人没用的邀请攒到 10 条 | 一行英文提示 | 说清楚怎么办：等对方用掉，或者点“撤销还没用的邀请”。24 小时有效期让这个上限更容易碰到，所以补了这句。上限本身没改 |
| 新人加入以后，负责人的成员列表 | 要手动刷新才看得到 | 几秒内自己出现 |

## 进到项目里以后

| 情况 | 以前 | 现在 |
| --- | --- | --- |
| 访客想发言 | 点发送，页面说“当前设备已退出，请重新配对后继续”，还跳到配对页（其实只是不能发言，设备没退出） | 输入框一开始就是灰的，写着“你是访客：能看对话，不能发言”。直接调接口发，服务器照样拒绝 |
| 负责人把你移出项目 | 同样说“当前设备已退出” | 几秒内页面变成“你已不在「…」里了”，点“回到我的对话”，你自己的对话不受影响 |
| 负责人改了你的权限 | 同样说“当前设备已退出” | 输入框当场变灰或者恢复，并说一声“你在这个项目里的权限变了：现在是…” |
| 别人的发言 | 也画成“我说的”，靠右，没有名字 | 靠左，标着名字；同一个人连着说，只标一次 |
| 项目的对话页 | 一直提示“有新版本” | 不再提示 |
| 自己的私人空间 | 叫“Personal” | 叫“个人空间”，助理还是栖序 |
| 负责人没给自己起过名字 | 别人看到的是“Owner” | 别人看到的是“负责人”（见下面“没动的”） |

## 顺手修的一处，和邀请无关

发布前跑随机测试时，找到知识库里一个 0.9.0 就有的问题：标题只有一段代码（例如 ``## `config.toml` ``）时，助手认不出这是个标题；标题里夹着代码（``## 运行 `pa doctor` ``）时，按完整文字也找不到这一节。后果是往这一节追加内容，每次都会多出一个同名标题。现在代码是标题文字的一部分；代码块和注释里写得像标题的内容，仍然不算标题。

## 没动的

- 负责人没有地方改自己的名字。数据库里存的是“Owner”，这一版只是让别人看到时显示成“负责人”。要显示真名，得加一个“改名字”的入口，这一版没做。
- 助手里的“加入项目”卡片，只有自动测试，没有在真实浏览器里走过。
- 只在 Chrome 里走过，没在真机的 iPhone Safari 上试。没登录时隐藏菜单用的是较新的样式写法（iOS 15.4 以上才认）；不认的话，加入页会多显示一列菜单，不影响加入。
- 邀请有效期固定 24 小时，不能改。一个人同时最多留 10 条没用的邀请，所有项目加起来算。
- 用恢复码登录，会作废你发出去的所有没用的邀请（原来就是这样）。有效期变成 24 小时以后，更容易碰上，已写进 [COLLABORATION.md](COLLABORATION.md) 的排查表。

## 更新与回退

先备份 `~/.personal-agent`（或你的 `PA_HOME`），再更新依赖并重启：

```bash
uv sync --frozen
uv run pa serve
```

正在运行的服务，代码是启动时读进内存的，重启之后才会换成这一版。网页文件的缓存名带着版本，重启后浏览器会自己换新。

要回退到 0.9.1，直接换回代码就行：数据库没有变化，不用恢复备份。已经发出去的 24 小时邀请，在 0.9.1 上同样有效，到期时间不变。
