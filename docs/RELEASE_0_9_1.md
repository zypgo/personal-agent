# 0.9.1：把代码过了一遍，修了十几处问题

这一版没有新功能。0.9.0 加了很多东西，这一版把新写的部分逐行读了一遍，再用自动检查扫了整个仓库，找到下面这些问题并修掉。每一处（放宽测试超时除外）都先写了一个在 0.9.0 上会失败的测试，再改代码，所以不会悄悄回来。

数据库还是 v15，没有新增依赖，接口没有变。

## 查了什么，没查什么

- **逐行读的**：0.9.0 新写的代码，也就是知识库（`vault/`）、任务线（`orchestration/threads.py`）、分条发，以及对应的网页和命令。
- **用工具扫的**：整个仓库。格式、规范、类型（`mypy` 严格模式）；整套测试在开发模式下再跑一遍，文件没关、协程没等待都当错误；所有正则用恶意输入量过时间；随机的怪文本喂给文本处理函数；属性测试加到每条 1000 组；故意改坏代码看测试能不能发现。
- **没做的**：0.9.0 之前的代码没有逐行重读，这一版没有发现它们的问题，不等于没有。谁也不能保证“一个 bug 都没有”，只能说：找到的都修了，也都有测试守着。

## 修了什么

### 知识库

| 问题 | 会怎样 | 现在 |
| --- | --- | --- |
| 解析笔记的几条正则，遇到一行很长的怪文本（标题、行内代码、链接）会越算越慢 | 一篇粘错了的或者别人写的笔记，能让服务卡住很久 | 标题改成手写解析，其他正则收紧，长怪文本也是毫秒级 |
| 网页上显示笔记时，`[[` 很多的文字有同样的问题 | 浏览器标签页卡死 | 同样改了 |
| `[vault] exclude` 只能写最外层的文件夹名，而且分大小写 | 想挡 `wiki/私人/`，写不出来；写 `private` 又挡不住叫 `Private` 的文件夹，助手都看得到 | 可以写路径（`wiki/私人`），不分大小写，里面的东西一起挡 |
| 名字里带点的笔记（`Node.js 笔记`）被当成附件 | 链接、反向链接、“链到了不存在的笔记”都算错 | 只有常见文件后缀（图片、PDF 等）才算附件 |
| 目录和记录（`wiki/index.md`、`wiki/log.md`）换个大小写（`Index.md`）就能写 | 在 macOS 默认的不分大小写的磁盘上，助手可以覆盖自动生成的目录 | 不分大小写都保护 |
| 属性块里只要有一处写错，`private: true` 就不生效 | 手滑少个冒号，这篇私密笔记对助手就是公开的 | 属性块读不出来时，也认 `private: true` 这一行 |
| 助手可以往私密笔记后面追加 | 读不到，却能写进去 | 不能写 |
| 文字里带着落单的代理字符（从网页或 PDF 复制时会带进来） | 写入时直接报错 | 先清掉再写 |
| 笔记已经保存好了，只是“记录”里那一行没写成功 | 页面说没保存成；如果是往后追加的内容，再试一次就多出一份 | 记录那一行写不成，只记日志，不影响保存 |

### 任务线

| 问题 | 会怎样 | 现在 |
| --- | --- | --- |
| 有一个任务的记录处理不了 | 后面所有任务的通知都发不出去，一直卡着 | 最多再试 3 次，然后跳过它，继续处理后面的 |
| 先写笔记，再通知你 | 笔记写失败，通知也跟着丢 | 先通知，再记笔记 |
| 跟进、巡检、写笔记，其中一个出错 | 同一轮里后面的步骤都不做了 | 各做各的，一个出错不连累别的 |
| 已经单独提醒过的事 | 后来三件以上合成一条时，又被说了一遍 | 说过的不再说 |
| 日记里的记号 `ev:12` 和 `ev:123` 互相“撞” | 第 123 号事件写过之后，第 12 号被当成写过了，日记里漏一行 | 整个记号对上才算 |
| “说过了”的记号从来不清理 | 越攒越多 | 任务收起时清掉；每天再清一次已经结束的任务 |

### 其他

| 问题 | 会怎样 | 现在 |
| --- | --- | --- |
| Telegram 消息里处理标题的正则，遇到很长的一行会越算越慢 | 3500 个字的一行，要算 27 秒 | 手写，毫秒级 |
| 同一处还有个小毛病：`# C#` 结尾的 `#` 被吃掉 | 标题显示成 `C` | 只去掉标题格式里的结尾 `#` |
| 识别假冒的“system:”开头，在有很多空行的文本里越算越慢 | 写记忆、写知识库、压缩对话时都会过这一步，大段文本会卡 | 改成不会越算越慢的写法 |
| 任务索引里找标题和状态的正则，同样的毛病 | 同上 | 同上 |
| 两个测试在电脑忙的时候偶尔失败 | 偶尔红一下 | 超时放到合理的值 |

另外补了数据库升级的测试：从 v1、v5、v8、v9、v14 升到 v15，旧数据一行不少。

## 验证

- `scripts/check.sh` 全部通过：格式、规范、类型（217 个源文件）、Python 测试 6195 个通过（30 个按平台或要花钱的真实调用跳过）、网页脚本测试 308 个通过。
- 开发模式下，把没关的文件、没等待的协程、线程里没处理的错误都当成失败，整套测试再跑一遍：还是 6195 个通过。
- 这一版新增 30 个 Python 测试，网页脚本新增 1 个测试、补了 1 处断言。把前 28 个拿到 0.9.0 的代码上跑：24 个失败或者卡住（其中 2 个卡在慢正则上，90 秒还没跑完，中途停掉了），网页脚本的 2 处也失败。剩下 4 个本来就该通过：旧数据库升级不丢数据、没被排除的文件夹没被误伤、改完后“假冒 system”仍然认得出来、任务索引的结果不变，它们是防止改过头的。后补的 2 个，守的是 0.9.0 就对、但一直没有测试盯着的行为（见“故意改坏”那一条）。
- 属性测试用 `thorough` 档（每条 1000 组随机输入）跑了一遍：982 个通过。
- 故意改坏代码、看测试能不能发现的名单 `scripts/mutation/lists/v09_knowledge_threads.py`，从 65 处增加到 83 处（新增的 18 处对应这一版的修复），整份重新跑了一遍。原来的 65 处里，有 5 处在 0.9.0 上其实没有测试守着：代码本身是对的，只是没有测试证明它。它们是：私密笔记不会列给助手；私密的原始资料不会被当成“等着整理”；助手只能往任务笔记的“笔记”一节里加内容；追加时带着过期的版本号会被拒绝；整篇改写忘了带版本号时，提示的是该带版本号。补了测试，现在 83 处都能被发现。
- 更早的名单里，目标文件在 0.8.1 之后动过的 165 处（梦、新会话、协作、数据、网页配置等）也重跑了一遍，都能被发现。
- 随机怪文本（19 个文本函数，两万多条输入，含落单代理字符、空字符、`[[`、反引号堆）没有一次报错，最慢的一次 2 毫秒。

## 已知但这一版没动

- 知识库的扫描和任务线的巡检还在服务的主循环里做。笔记不多时没有感觉；放到上限（5000 篇）附近，一次扫描会占用一小会儿。
- `[vault] exclude` 里的文件夹，网页的知识库页也看不到。想看它们，用 Obsidian 打开。

## 更新与回退

先备份 `~/.personal-agent`（或你的 `PA_HOME`），再更新依赖并重启：

```bash
uv sync --frozen
uv run pa serve
```

正在运行的服务，代码是启动时读进内存的，重启之后才会换成这一版。网页文件的缓存名带着版本，重启后浏览器会自己换新。

要回退到 0.9.0，直接换回代码就行：数据库没有变化，不用恢复备份。
