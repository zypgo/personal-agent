# 使用你的 Personal Agent

Personal Agent 打开后进入聊天。把目标告诉它，让它查询已有信息、准备工作并持续跟进；需要你决定的事情，在对话中的卡片里处理。左侧菜单提供同一套任务、资料与连接的管理页面。

## 开始第一件事

完成部署和浏览器配对后，打开 **个人助理**。先从一个明确的小任务开始，例如“帮我整理这段资料”“提醒我明天处理这件事”或“看看有哪些任务需要我回答”。页面上的快捷入口会把示例填入输入框，你可以修改后再发送。

个人助理使用菜单中选中的空间。私人空间用于自己的对话、记忆和任务；项目空间用于与该项目的成员协作。切换空间后，助理能看到的资料、任务与可用资源也随之改变。

## 菜单里的功能

点击左上角菜单按钮，可以展开或收起导航。电脑记住菜单的展开选择；手机默认收起，在页面空白处向右拖动即可拉出，向左拖动、点遮罩或按 Escape 可关闭。

| 页面 | 日常用途 |
| --- | --- |
| 个人助理 | 对话、查看待办卡片，提出下一件事 |
| 任务 | 查看助手协作和电脑任务，核对计划与成果 |
| 资料 | 搜索、创建、编辑资料，查看历史版本 |
| 助手与连接 | 接入已有 Agent，管理连接和使用范围 |
| 项目与成员 | 建立共享项目，邀请成员和管理角色 |
| 设备与账号 | 连接电脑、登录其他设备、绑定聊天账号、准备恢复码 |

同一个空间内切换功能页面，未提交的表单仍会保留。离开页面或切换空间前，有未保存内容时会提醒；资料正在保存时，需要等本次保存结束再打开另一份。草稿不会额外写入浏览器存储。

页面可直接收藏，例如 `/workspace?tab=knowledge`。带 `space` 的地址会保留选中的空间；分享地址不会同时分享账号或权限。

## 日常使用

### 整理资料与记住上下文

可以让助理查找已有记忆、把零散信息整理为笔记，或准备一份项目资料更新。请指出希望保存在哪个项目；不明确时，助理应先询问。资料更新遵守版本检查，较旧内容不会覆盖已经提交的新版本。

例如：“把刚才讨论的旅行安排整理成一份资料，放进旅行项目。”助理需要使用该项目时，你先切换到对应空间；私人资料不会因为一句模糊的指令被转移到共同项目。

### 定时跟进

直接说明时间、重复频率和期望结果，例如：“工作日早上八点给我一份行业简报，有变化时重点说明。”定时任务使用已配置的时区与通知渠道。助理保留任务进度和近期已经通知过的内容，执行情况可以随时询问。

网页不是系统推送服务。需要在关闭页面后收到主动消息，请配置 Telegram 或钉钉，并完成账号与空间绑定。

### 把工作交给电脑或其他 Agent

告诉助理目标、希望使用的资料及完成标准。它会查询已接入且有权使用的执行端，准备执行或协作计划。确认卡片会展示将要执行的内容；只有授权通过后才派发。

多个 Agent 可以并行处理、依次接力或在并行后汇总。后继步骤需要前置成果通过验收。收到一个 webhook、领取到任务、完成执行与通过验收，是不同状态，助理不会把它们混为完成。

设备离线时，相关执行任务等待上线。服务正常运行的情况下，你仍可查看任务和进行其他对话。

## 在个人助理里做决定

| 卡片 | 你需要判断什么 | 操作结果 |
| --- | --- | --- |
| 执行审批 | 将执行的内容、输入与输出、使用的电脑 | 批准或拒绝这份确定的计划 |
| Agent 协作计划 | 目标、接收方、外发内容、步骤与验收标准 | 确认后才能派发 |
| 补充问题 | 当前执行端需要的答案或选择 | 回答后等待执行端继续处理 |
| 待验收成果 | 结果正文、文件、是否达到标准 | 通过验收后，依赖它的步骤才能继续 |
| 管理操作 | 项目、成员、资料、设备或连接的具体变化 | 在安全表单里确认并执行 |

卡片会根据当前身份、空间和资源权限提供可用操作。没有审批权限的人不会通过自然语言获得额外权限。已经处理、过期、失权或执行状态不明的卡片，不会再次显示为可以直接执行的新请求。

邀请、配对码、恢复信息和连接凭据只显示在受保护的界面中。不要把它们粘贴到聊天、项目资料或任务说明里；模型也不会收到这些值。

已有项目邀请码时，可以说“帮我加入一个项目”。在助理打开的安全表单中输入代码，会使用当前账号加入；邀请码不进入对话，账号失效时也不会自动创建另一个身份。

## 查看进度与处理阻塞

可以直接问“这件事到哪一步了”“哪些地方需要我处理”“成果在哪里”。需要总览时，从菜单打开 **任务**；任务、资料和连接页面与助理使用同一份数据。

如果一次操作可能已经提交，但没有收到确定回复，个人助理会保留待核查状态。先检查对应任务或连接，再决定下一步。不要用刷新页面、重复点击或新建相同任务来判断执行是否成功。

审批或补充回答提交失败时，先点卡片区域的刷新。服务端仍允许处理的卡片会重新开放，并要求你重新核对；页面不会自动重复提交。已开始执行或结果不明确的管理操作仍保持待核查状态。

停止任务也是一个过程：提交取消后，要等实际执行端确认停止。对外部 Agent，必要时还要在原生产品中核对执行状态。

## 能力由你的连接决定

模型、搜索、语音、聊天渠道、执行电脑及外部 Agent 都需要各自配置。Grok 使用已配置的 Routine 自动唤醒；Muse 通过原生会话或定时能力领取；Codex、Cursor 使用你自己的电脑与原生登录。注册一个连接不代表它已经通过真实执行验收。
