# 0.6.0：聊天首页与产品菜单

## 这一版的目标

你从对话进入 Personal Agent，用自然语言和交互卡片完成日常工作；需要查看、编辑或管理的时候，再打开对应的功能页面。原来的工作台，变成了一个可以收起的菜单，底层的能力沿用 0.5.0。

这一版没有引入新的服务、付费沙箱、前端依赖或数据库迁移。API 字段和执行协议都没变；后端只修了一个问题：旧的权限卡片，占着当前的额度。

## 页面与动线

| 页面 | 第一件事 | 次要操作，和保留的能力 |
| --- | --- | --- |
| 个人助理 | 写下你想完成的事 | 快捷起点、流式回复、图片、语音、历史、审批和待办卡片 |
| 任务 | 看进度，和需要你自己处理的事项 | 在助手协作 / 电脑任务之间切换，计划审批、提问、结果验收、日志和文件 |
| 资料 | 搜索或打开已有的资料 | 新建、编辑、保存、历史版本；保存时固定当前这份资料 |
| 助手与连接 | 查看已经接入的助手 | 新建连接、编辑、轮换凭据、撤销、接入文件和停止核对 |
| 项目与成员 | 查看当前的成员和角色 | 创建项目、生成邀请、修改角色、移除成员、加入项目 |
| 设备与账号 | 查看你自己的设备和连接 | 配对、撤销、执行电脑、Telegram/钉钉绑定、恢复码、退出 |

导航用的是同一份固定的目的地列表。桌面端默认展开，并记住你收起的选择；手机默认关闭，展开之后，会锁定背景、约束键盘焦点；点遮罩或按 Escape 关闭之后，焦点还给菜单按钮。系统设置了“减少动态效果”的话，抽屉动画会关掉。

聊天的欢迎区给了明确的起点，输入框、消息和确认卡片，统一用原来的暖纸色和系统字体。设置里展示运行状态、今日花费、待确认的数量和设备信息；完整的状态查询，仍然通过原有的 `/status` 命令。没有加入虚构的任务、假数字，或者没有实际动作的按钮。

原来的 `/workspace` 继续打开任务页。`?tab=tasks|knowledge|agents|spaces|devices` 定位栏目；`?tab=tasks&view=computer` 定位电脑任务。前进后退和刷新，会保留栏目和当前空间，不认识的栏目，回到真实的任务页。

### 设计参考与判断

单层侧栏和主要的对话区域，参考了实际看过的 [WRITER](https://mobbin.com/screens/c3f8b744-4ff6-4f1c-8d95-5d9f56da86a3?utm_source=chatgpt&utm_medium=ai-assistant&utm_source_platform=mcp)、[ChatGPT](https://mobbin.com/screens/efb593c5-be61-47d5-a2bd-87aab6056cd2?utm_source=chatgpt&utm_medium=ai-assistant&utm_source_platform=mcp) 和 [Notion](https://mobbin.com/screens/9a9b1268-e0d5-4873-900b-aa75e9a81177?utm_source=chatgpt&utm_medium=ai-assistant&utm_source_platform=mcp) 页面。只采用了它们可见的导航和对话的布局关系，配色、字体、数据和权限，仍然沿用 Personal Agent 自己的。具体的栏目命名、表单分组、移动端抽屉的行为和草稿保护，是本项目根据现有能力做出的设计判断，不声称这些参考证明了行为指标的改善。

## 复核发现的问题，和修复

| 问题 | 对你的影响 | 怎么修的，怎么验证 |
| --- | --- | --- |
| 成员请求，仍然带着旧的 `action` 字段 | 修改或移除成员，被严格的契约拒绝 | 改用当前的 DTO，用真实的前端请求做回归 |
| 已登录的人接受邀请，没有钉住现有会话 | 撤权之后，存在错误的恢复路径 | 提交 `require_existing_session: true`；复用已有的身份 / 事务边界测试 |
| 旧的权限提案，仍然计入 40 张的上限 | 看不到待办，却又不能生成新卡片 | 只对当前的权限版本计数；旧的执行回执仍然保留，禁止重试的语义不变 |
| 审批 / 取消失败之后，卡片一直被锁定 | 刷新也没法继续处理 | 失败之后，要等新的授权读取，才恢复，重新核对后再操作；在途的请求，和旧的读取，不能提前解锁 |
| 退出之后，录音 / 音频解析继续完成 | 旧的媒体，可能进入之后登录的对话 | 销毁时取消录音，异步边界检查当前的 UI 身份 |
| 重复登录，累积拖放和视口监听 | 图片被重复添加，旧页面的回调继续运行 | 随页面销毁而解绑，清理观察器和弹窗 |
| 并发的图片导入，按旧的容量计算 | 超出图片数量，或者图片还没准备好就发送 | 导入之前先预留数量，准备完成之后，才允许发送 |
| 录音器构造 / 启动失败，漏了清理 | 麦克风音轨没有释放 | 初始化异常，也会执行幂等的释放，保留正常的录制和取消 |
| 保存资料时，允许切换编辑的对象 | 旧的响应，覆盖了新资料的版本和草稿标记 | 保存期间，禁止打开 / 新建 / 关闭资料，完成之后再切换 |
| 凭据和邀请的按钮，可以被重复点击 | 生成多次操作，或者覆盖一次性的信息 | 提交期间锁定按钮，完成后恢复 |
| 退出请求失败，仍然显示已退出 | 实际的登录状态，和界面提示不一致 | 明确区分“本地已清空”和“服务端已确认” |
| 离开页面或切换空间，没有草稿保护 | 没发送的文字、附件或表单内容，会丢 | 只在确实有没保存的内容时提醒；不把私密草稿持久化 |

## 升级与回退

按现有的部署流程更新，保留原来的持久卷和配置，运行 `uv sync --frozen` 之后重启。静态资产的版本，由实际的文件内容生成，服务工作线程更新的时候，会包含新的菜单文件；私密 API 和凭据，不进入离线缓存。

这一版没有 schema 迁移。需要回退的话，可以重新部署 0.5.0；不会删除持久化的数据、任务或操作回执。
