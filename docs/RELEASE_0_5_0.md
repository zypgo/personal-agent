# 0.5.0：个人 Agent 产品化

## 产品目标

让用户通过“告诉助理目标 → 跟进进度 → 回答必要问题 → 收取成果”完成日常工作。工作台保留为管理与检查视图，Agent 能发现、查询和准备这些管理能力，用户不必先理解内部服务与协议。

主导航只有两个入口：**个人助理**和**工作台**。任务、资料、连接与身份仍来自原有业务系统，不创建第二套任务状态或权限。

## 本次迭代

| 方向 | 产品变化 | 实现方式 |
| --- | --- | --- |
| 入口 | 个人助理成为默认入口，提供日常任务的自然语言起点 | 两个主导航入口、个人助理空态和输入提示 |
| 能力发现 | 助理先查明当前能够做什么 | 能力目录工具、按身份与空间授权的查询 |
| 自然语言操作 | 对话发起资料、项目、成员、设备与连接等管理需求 | 受限操作目录、持久操作提案、安全表单 |
| 决策闭环 | 在个人助理处理计划、问题和成果 | 从真实业务状态生成的审批、回答与验收卡片 |
| 过程反馈 | 卡片变化及时回到当前页面 | SSE 变化通知、可见页面刷新与断线恢复 |
| 防止重复 | 不把网络断开误认为操作尚未执行 | 执行前持久开始标记、明确成功回执、未知状态保留核查 |
| 表达 | 用目标、影响、下一步解释工作 | 助理系统指令与面向个人用户的使用说明 |

## 能力与权限

日常对话、记忆、历史检索、提醒、执行任务与 Agent 协作继续使用原有工具。新增的能力目录、状态检查与操作准备工具，将管理能力纳入同一个助理流程。

### 工作台能力如何进入助理

| 用户要做的事 | 助理入口 | 处理方式 |
| --- | --- | --- |
| 查待办、进度、成员、设备、连接、资料历史和执行日志 | `workspace_capabilities`、`inspect_workspace` | 发现当前身份能用的能力，按当前空间查询；包含 17 类查询主题 |
| 记住信息、查历史、安排提醒 | 原有记忆、搜索与 `schedule` 工具 | 按原有工具策略处理；提醒沿用已配置时区与渠道 |
| 交办电脑任务、提问、查进度、取消 | `submit_job`、`ask_task_input`、`job_status`、`cancel_job` | 模型可以准备工作和请求停止；资源授权仍由人决定 |
| 多个 Agent 分工与接力 | `list_agents`、`delegate_agents`、`agent_task_status`、`cancel_agent_task` | 准备明确的接收方、外发内容、依赖和验收标准；确认后派发 |
| 查看 Agent 接入指引、下载连接文件 | 连接安全窗口、编辑连接中的折叠指引 | 提供 MCP / OpenAPI 地址、协议说明和固定接口的 OpenAPI / Bridge 下载；无需离开个人助理 |
| 创建项目、邀请或调整成员、加入已有项目 | 4 类管理操作卡片 | 填写具体内容；接受邀请时只使用当前有效账号，邀请码仅在表单中传递 |
| 配对、撤销本人设备与重新生成恢复码 | 3 类设备操作卡片 | 在受保护的界面完成；一次性代码不进入对话 |
| 绑定或撤销聊天渠道 | 2 类渠道操作卡片 | 沿用当前身份与空间的固定绑定 |
| 接入或撤销执行电脑 | 2 类节点操作卡片 | 核对电脑及可用空间，执行原有管理员权限检查 |
| 保存或更新资料 | 1 类资料操作卡片 | 用户可编辑草稿，提交时检查资料版本 |
| 创建、修改、追加步骤或取消电脑任务 | 4 类任务操作卡片 | 与工作台使用同一任务状态与版本，执行前另行审批 |
| 连接、编辑、更新凭据或撤销 Agent | 4 类连接操作卡片 | 明确连接对象和可用范围；凭据仅在安全窗口显示 |
| 创建或取消 Agent 任务、确认执行或唤醒已停止 | 4 类协作操作卡片 | 对停止确认核对当前执行实例，由资源持有人亲自说明核查依据 |

管理操作共 **24 类**。已有工作台的执行审批、计划确认、回答问题和成果验收，直接使用由真实业务状态生成的卡片。未登录时的注册、恢复访问，以及当前设备退出，继续由账户界面处理。

模型可以查询被授权的数据并准备一张具体操作卡片；它没有用用户身份点击确认、批准自己的计划、验收自己的成果或读取一次性凭据的工具。用户操作继续经过既有业务接口、当前会话、成员权限、计划摘要和版本检查。

模型读取严格限定在当前空间。资源持有人需要审核其他空间的电脑计划时，仅在本人私人界面显示审批内容；这些内容不会因为管理员身份被带入共享对话。资源持有人确认别人的私有 Agent 任务已停止时，只能看到必要的占用与执行标识，不能读取对方任务正文。

操作提案保存在所属空间的既有数据库中，记录发起人、授权版本、有效期与执行状态。数据不写入浏览器持久存储。卡片查询不创建新的任务或管理操作；任务过期等状态继续按原有规则核对。

## 交互与失败处理

1. 用户提出需求，助理查询当前状态并准备必要的计划或表单。
2. 当前用户查看实际内容、影响及目标对象后操作卡片。
3. 管理提案先保存开始状态，再调用对应的固定业务操作。
4. 明确收到成功结果后保存完成记录；凭据只留在受保护的界面，不进入提案回执或模型上下文。
5. 如果执行结果不明确，卡片保持待核查状态；重载页面不会恢复为可直接重复执行。

输入中的表单不会因为相同状态的轮询而重置；失效卡片会立即禁用。主动离开项目后返回个人空间，权限降级后刷新可用操作。页面切换和注销会清除安全表单与一次性凭据窗口。

执行任务与多 Agent 协作继续使用原有幂等、版本、计划摘要和人工验收机制。卡片是这些机制的产品入口，不替换原有授权。

## 升级

先备份实例和持久卷。更新代码与既定依赖后重启单个控制进程：

```bash
uv sync --frozen
uv run pa serve
```

维护前端的开发环境继续执行 `npm ci` 与 `npm run check`。部署安装包内已包含静态页面与浏览器依赖，无需在运行服务时另启 Node 服务。

本次没有增加外部服务、付费云沙箱或新的凭据托管方。现有任务、Agent、执行节点和成员继续使用原来的注册及权限。

## 验收范围

跨层验证使用真实应用、权限、数据库、工具运行和业务 HTTP 接口，模型及执行端由脚本替代：

- **资料流程**：对话发现能力 → 准备资料卡片 → 用户改稿 → 确认保存 → 下一轮助理查询到新内容。
- **Agent 流程**：对话准备计划 → 用户确认 → 执行端领取 → 提问与回答 → 回传文件 → 鉴权下载 → 用户验收 → 状态完成。
- **故障与权限**：并发点击、丢失回复、重载页面、读取请求期间撤权、成员重入、私有任务隔离、邀请码不落盘、资源持有人核对停止。

本次没有调用真实模型或外部 Agent 账号。云端浏览器无法访问隔离的本地预览地址，因此**没有完成真实桌面/手机浏览器的视觉验收**；前端交互由 DOM 与纯逻辑回归验证。部署后的真实账号连接、设备布局和触控体验仍需实际验证。
