# 0.5.0：个人 Agent 产品化

## 目标

让你用这样的方式完成日常工作：告诉助理你要什么 → 跟进进度 → 回答必要的问题 → 收下成果。工作台保留，用来管理和检查；Agent 能发现、查询并准备这些管理能力，你不用先弄懂内部的服务和协议。

主导航只有两个入口：**个人助理**和**工作台**。任务、资料、连接和身份，仍然来自原来的业务系统，没有另建第二套任务状态或权限。

## 这一版改了什么

| 方向 | 产品上的变化 | 怎么实现的 |
| --- | --- | --- |
| 入口 | 个人助理成为默认入口，用自然语言开始日常任务 | 两个主导航入口、个人助理的空状态和输入提示 |
| 能力发现 | 助理先查清楚，现在能做什么 | 能力目录工具、按身份和空间授权的查询 |
| 自然语言操作 | 在对话里提出资料、项目、成员、设备和连接等管理需求 | 受限的操作目录、持久的操作提案、安全表单 |
| 做决定 | 在个人助理里处理计划、问题和成果 | 根据真实业务状态生成的审批、回答和验收卡片 |
| 过程反馈 | 卡片有变化，马上回到当前页面 | SSE 变化通知、可见页面的刷新，和断线恢复 |
| 防止重复 | 不把“网络断了”，当成“操作还没执行” | 执行之前先持久化开始标记、明确的成功回执，结果不明时保留核查 |
| 表达 | 用目标、影响、下一步，来解释工作 | 助理的系统指令，和面向个人用户的使用说明 |

## 能力和权限

日常对话、记忆、历史检索、提醒、执行任务和 Agent 协作，继续用原来的工具。新增的能力目录、状态检查和操作准备工具，把管理能力放进同一个助理流程里。

### 工作台的能力，怎么进到助理里

| 你要做的事 | 助理的入口 | 怎么处理 |
| --- | --- | --- |
| 查待办、进度、成员、设备、连接、资料历史和执行日志 | `workspace_capabilities`、`inspect_workspace` | 找出当前身份能用的能力，按当前空间查询；包含 17 类查询主题 |
| 记住信息、查历史、安排提醒 | 原有的记忆、搜索和 `schedule` 工具 | 按原有的工具策略处理；提醒沿用已经配置的时区和渠道 |
| 交办电脑任务、提问、查进度、取消 | `submit_job`、`ask_task_input`、`job_status`、`cancel_job` | 模型可以准备工作、请求停止；资源授权仍然由人决定 |
| 多个 Agent 分工、接力 | `list_agents`、`delegate_agents`、`agent_task_status`、`cancel_agent_task` | 准备好明确的接收方、外发内容、依赖和验收标准；你确认之后才派发 |
| 查看 Agent 的接入指引、下载连接文件 | 连接的安全窗口、编辑连接里折叠的指引 | 提供 MCP / OpenAPI 地址、协议说明，以及固定接口的 OpenAPI / Bridge 下载；不用离开个人助理 |
| 创建项目、邀请或调整成员、加入已有项目 | 4 类管理操作卡片 | 填写具体内容；接受邀请时，只使用当前有效的账号，邀请码只在表单里传递 |
| 配对、撤销本人的设备，重新生成恢复码 | 3 类设备操作卡片 | 在受保护的界面里完成；一次性代码不进入对话 |
| 绑定或撤销聊天渠道 | 2 类渠道操作卡片 | 沿用当前身份和空间的固定绑定 |
| 接入或撤销执行电脑 | 2 类节点操作卡片 | 核对电脑和可用的空间，执行原有的管理员权限检查 |
| 保存或更新资料 | 1 类资料操作卡片 | 你可以编辑草稿，提交时检查资料版本 |
| 创建、修改、追加步骤或取消电脑任务 | 4 类任务操作卡片 | 和工作台用同一套任务状态和版本，执行之前另行审批 |
| 连接、编辑、更新凭据或撤销 Agent | 4 类连接操作卡片 | 明确连接的对象和可用范围；凭据只在安全窗口里显示 |
| 创建或取消 Agent 任务、确认执行或唤醒已停止 | 4 类协作操作卡片 | 对停止确认，核对当前的执行实例，由资源持有人亲自说明核查的依据 |

管理操作一共 **24 类**。已有工作台里的执行审批、计划确认、回答问题和成果验收，直接用根据真实业务状态生成的卡片。没登录时的注册、恢复访问，和当前设备的退出，仍然由账户界面处理。

模型可以查询你被授权的数据，并准备一张具体的操作卡片；它没有这些工具：用你的身份点确认、批准自己的计划、验收自己的成果，或者读取一次性的凭据。你的操作，仍然要经过原有的业务接口、当前会话、成员权限、计划摘要和版本检查。

模型读取的范围，严格限定在当前空间。资源持有人要审核其他空间的电脑计划时，审批内容只在他本人的私人界面里显示；这些内容，不会因为他是管理员，就被带进共享的对话。资源持有人确认别人的私有 Agent 任务已经停止时，只能看到必要的占用和执行标识，读不到对方任务的正文。

操作提案保存在所属空间已有的数据库里，记录发起人、授权版本、有效期和执行状态。数据不会写进浏览器的持久存储。卡片的查询，不会创建新的任务或管理操作；任务过期等状态，继续按原有的规则核对。

## 交互与失败处理

1. 你提出需求，助理查询当前状态，准备必要的计划或表单。
2. 你看过实际的内容、影响和目标对象之后，再操作卡片。
3. 管理提案先保存“开始”状态，再调用对应的固定业务操作。
4. 明确收到成功结果之后，才保存完成记录；凭据只留在受保护的界面里，不进入提案回执，也不进入模型上下文。
5. 如果执行结果不明确，卡片保持“待核查”；重新加载页面，也不会变回可以直接重复执行的状态。

你正在输入的表单，不会因为相同状态的轮询而被重置；失效的卡片会立刻禁用。你主动离开项目、回到个人空间，或者权限降级之后，可用的操作会刷新。切换页面和注销，会清掉安全表单和一次性凭据的窗口。

执行任务和多 Agent 协作，继续用原来的幂等、版本、计划摘要和人工验收机制。卡片是这些机制在产品里的入口，不替换原来的授权。

## 升级

先备份实例和持久卷。更新代码和既定的依赖，再重启单个服务进程：

```bash
uv sync --frozen
uv run pa serve
```

维护前端的开发环境，继续执行 `npm ci` 和 `npm run check`。部署的安装包里，已经带上了静态页面和浏览器依赖，运行服务时不用另外启动 Node 服务。

这一版没有增加外部服务、付费云沙箱或新的凭据托管方。现有的任务、Agent、执行节点和成员，继续用原来的注册和权限。
