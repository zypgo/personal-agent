# Browser adapters

The existing page code stays in `src/personal_agent/channels/web/static/`. This folder holds the TypeScript parts: how requests are sent, how Markdown is turned into safe display data, and how task forms are built. TypeScript is being added step by step. The whole UI is not TypeScript or React.

## Build and check

You need Node 22.12 or newer, and the project's Python development environment:

```sh
uv sync --frozen --group dev
npm ci
npm run build
npm run check
```

`npm run build` checks the generated API types, type-checks the adapters and runs Vite. It only needs Node and the checked-in schema. It writes `static/query.js`, `static/markdown-parser.js` and `static/THIRD_PARTY_NOTICES.txt`; commit all three. Python serves the compiled JavaScript as it is, including from the wheel. Neither Node nor a CDN is needed when the service starts.

`npm run check` does more. It exports the live Python API contract into a temporary folder and compares it with the committed OpenAPI JSON. It checks the generated TypeScript and both bundles byte for byte, checks the licenses of the modules that were actually bundled, and runs all browser JavaScript tests. It finds Python through `PYTHON`, then `.venv`, then `python3`. It never downloads dependencies and never opens the agent's data. `npm test` runs only the JavaScript tests against the shipped assets.

After you change the API models or the app version:

```sh
uv run --frozen python scripts/export_api_schema.py
npm run generate:api
npm run build
npm run check
```

`frontend/generated/api.d.ts` is generated by openapi-typescript. `contracts.ts` uses those types to build the real task, step and answer payloads. The older, detailed task view models are still in `static/workbench.d.ts`. That does not mean every legacy page is strictly type-checked.

## Requests and privacy

`RequestScope` uses TanStack Query Core to merge simultaneous GET requests, track request state and cancel requests. Each query includes the principal and the space, plus a session epoch. Stale time and cache retention for unused data are both zero, so every later read goes back to the server for authorization. Nothing is persisted. There is no offline replay, no refetch on focus and no automatic retry. If a caller passes its own abort signal, it gets an independent query, so cancelling it cannot cancel another consumer.

Writes and binary downloads bypass the query and mutation cache. A write is sent once, with the caller's own idempotency key if the endpoint supports one. A lost response never proves that the write did not happen. When a write finishes, even with an error response, older reads are cancelled before the UI's next refresh. When the session or the space changes, downloads are revoked together with reads. Before any value is returned, the response body is checked against the epoch once more.

A 401 or 403 clears private requests and tells the page right away. This clears what is already on screen, even if cancellation wins a race inside a parallel `Promise.all`. The workbench can then fall back to the personal space that is left. The Service Worker caches only the new public assets and still leaves out `/api/` responses. Browser storage still holds only the display theme.

## Markdown

markdown-it parses CommonMark tokens with raw HTML turned off, and its HTML renderer is never called. The adapter produces a small data tree of allowed elements. The existing DOM renderer builds the page only from DOM nodes and text. It checks URLs again, allows only HTTP, HTTPS and mailto links, and shows images as labels or links without loading them.

The limits are unchanged: 60,000 characters per document, 20,000 characters per inline fragment, six levels of DOM nesting, 200 table body rows and 20 columns. Content over a limit, or nested too deeply, falls back to plain text. Reference links and entity decoding now use the standard parser. Badly nested link syntax follows CommonMark: it may produce separate autolinks, but never nested anchors.

Dependency versions are pinned in `package.json` and `package-lock.json`. TypeScript 5.9.3 fits the TypeScript 5 peer range that openapi-typescript 7.13 declares. Upgrade the two together when the generator supports a newer major version. Do not silence peer-dependency conflicts.
